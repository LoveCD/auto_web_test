# Workflow: generate-cases

## Role

你是 QCoder Web 自动化测试智能体，面向国际网关基线版本 Web 后台接口和页面生成自动化测试用例。

## Input

- 需求或接口说明：`requirements/*.md`
- 已有用例格式：`cases/**/*.json`（API 用例）、`cases/**/*.yaml`（Web UI 用例）
- 设备 Profile：`profiles/*.json`（API）、`profiles/*.yaml`（Web UI selector）

## Steps

### 通用步骤

1. 识别测试模块：从 `requirements/<product>_scope.md` 提取模块列表（不要写死固定模块）。
2. 提取接口/页面行为、字段、约束和错误路径。
3. 按 P0/P1/P2 生成测试点。
4. 标记 `module`、`priority`、`tags`（使用受控词表，见 Quality Rules）。
5. 给出需要新增的 runner action 或 profile API path / selector。

### API 用例生成

1. 提取接口行为、字段、约束和错误路径。
2. 输出可执行 JSON 用例，使用 `api.*` action。
3. P0 覆盖登录、状态查询、关键配置查询。
4. P1 覆盖边界、非法输入、未授权访问、配置保存后一致性。
5. BVA 三点法与 CRUD 一致性规则同样适用于 API 用例（见 Quality Rules）。
6. 给出需要新增的 runner action 或 profile API path。

### Web UI 用例生成

1. 识别页面模块：Login、Status、WiFi、WAN、System 页面。
2. 提取页面元素、表单字段、交互行为和验证点。
3. 按 P0/P1/P2 生成 Web UI 测试点。
4. 输出 YAML 格式用例，使用 `web.*` action（如 `web.navigate`、`web.login`、`web.fill`、`web.click`、`web.assert_text`、`web.assert_visible`）。
5. 标记需要新增的 Page Object 方法和 selector。
6. 确保每个用例以 `web.navigate` 开始，建立页面上下文。
7. 登录场景使用 `web.login` action，并显式声明预期：`expect: true`（登录成功）或 `expect: false`（登录失败），禁止框架隐式推断预期结果。
8. 负向场景使用 `expect: false` 标记不应出现的元素。
9. 未授权访问：每个受保护页面至少生成 1 条“未登录直接访问 → 跳转登录页”用例（P1，tags 含 negative）。
10. 配置恢复：配置修改类用例最后必须恢复基线配置（如改 SSID 后改回原值），保证用例可重复执行、不污染设备状态。
11. 参数关联：字段之间存在联动/依赖时（如 WAN 类型切换、开关与表单联动），按判定表生成组合用例，覆盖每个规则分支。
12. 参数化：同一边界/等价类模板的多组数据使用 `data_set` 列表，避免逐条手写重复用例。
13. 特殊字符：每个文本输入字段按字符集等价类生成用例（见 Quality Rules 等价类表）。
14. 多语言（i18n）：国际版产品涉及语言切换功能时，验证切换后文案变化、配置不丢失、切回后显示正常。

## Output

必须输出：

```text
1. 用例列表
2. 新增/修改的 JSON/YAML 用例
3. 覆盖点说明
4. 需要补充的执行关键字（api.* 或 web.*）
5. 需要补充的 selector 或 Page Object 方法
6. 人工审核注意事项
```

## Quality Rules

### 基础规则

- P0 覆盖登录、状态查询、关键配置查询。
- P1 覆盖边界、非法输入、未授权访问、配置保存后一致性。
- 用例必须可重复执行，不依赖上一次执行残留状态。
- 不直接写死真实密码到报告中。
- Web UI 用例的 selector_key 必须在 selector profile 中有对应定义。
- Web UI 用例的负向断言必须使用 `expect: false`，不要依赖异常捕获。
- `web.login` 必须显式声明 `expect: true/false`，禁止框架隐式推断预期结果。

### 优先级定义（完整）

| 优先级 | 定义 | 典型场景 | 准入要求 |
|---|---|---|---|
| P0 | 核心功能正常路径 | 登录、状态显示、配置保存成功、持久化 | 版本准入必过 |
| P1 | 边界、负向、安全、一致性 | BVA 三点、非法输入、未授权、CRUD 回读 | 回归必过 |
| P2 | 补充场景 | i18n、性能、容量、兼容性 L2 | 按产品阶段要求 |

### tags 受控词表

| 类别 | 合法值 |
|---|---|
| 套件 | smoke、regression |
| 类型 | positive、negative、boundary |
| 专项 | crud、persist、security、i18n、perf、capacity、compat |
| 模块 | login、status、wifi、wan、system（与 module 字段小写对应） |

禁止自造标签；新增标签须先扩展本词表，否则覆盖统计会失真。

### 等价类划分（字符集）

每个文本输入字段必须划分有效/无效等价类并各取代表值：

| 等价类 | 示例（SSID 字段） | 预期 |
|---|---|---|
| 有效-ASCII 字母数字 | `HomeWiFi` | 接受 |
| 有效-支持的符号 | `Home-5G_2.4` | 接受 |
| 有效-UTF-8 多语言 | `家庭网络` / `Réseau-5G` | 按产品规格 |
| 无效-前后空格 | `" WiFi "` | 按产品规格（去空格或拒绝） |
| 无效-emoji/控制字符 | `"\u{1F4F6}WiFi"` | 按产品规格 |
| 无效-注入载荷 | `"'><script>alert(1)</script>` | 拒绝或转义，不得执行 |

注意：长度约束按字节还是字符计算需在需求中确认，两类口径分别设计用例。

### 等待策略

- 优先依赖 Playwright 自动等待（auto-wait），不要在用例中添加固定 `web.wait`。
- `web.wait` 仅用于无信号可等待的场景（如重启倒计时），单次不超过 5s，并在用例中注明原因。
- 禁止用 sleep 掩盖竞态问题；等待不稳应上报框架层解决。

### 用例执行约束

- 单用例执行超时上限：120s（含导航），超时视为用例失败而非挂死。
- 用例必须支持并行执行：不得依赖共享浏览器 context、共享设备状态或执行顺序。
- 失败重试：允许 P0 用例自动重试 1 次，重试仍失败才判定失败并标记 flaky。

### 边界值分析（BVA）三点法

每个数值/长度约束必须生成三类用例，缺一不可：

| 取点 | 定义 | 示例（密码长度 10-63） | 预期 |
|---|---|---|---|
| 上点 | 最小/最大有效值 | 长度 10、长度 63 | 通过 |
| 内点 | 典型有效值 | 长度 32 | 通过 |
| 离点 | 边界外 ±1 | 长度 9、长度 64 | 拒绝 |

禁止只生成“越界拒绝”用例而缺失“界内通过”用例，否则无法发现“边界配置过严”缺陷。

### CRUD 一致性（write-read-verify）

- 增/删/改操作后必须回读验证：保存成功后重新进入页面或刷新，断言显示值与提交值一致。
- 仅有 success_message 可见性断言不算完成一致性检查。
- 跨页一致性：一处修改影响另一处显示时（如 Wi-Fi 页与状态页的 SSID），两处都要断言。

## Selector 策略（不改前端代码）

新设备接入时，按以下优先级在 Profile 中填写 selector。
注意：国际版本 UI 文本随语言切换变化，文本型 selector（`:has-text`）一律不作为首选：

| 优先级 | 策略 | 示例 | 适用元素 | 稳定性 |
|---|---|---|---|---|
| 1 | `input[name='xxx']` | `input[name='ssid']` | 表单输入框 | 最高（表单提交必须用） |
| 2 | `button[type='submit']` | `button[type='submit']` | 提交按钮 | 高 |
| 3 | `input[type='checkbox']` | `input[type='checkbox']` | 复选框 | 高 |
| 4 | `#id` | `#software-version` | 展示型元素（td/div） | 中（前端可能改 id） |
| 5 | `button:has-text('XX')` | `button:has-text('Save')` | 按钮兜底（i18n 文本会变，降级使用） | 中低 |
| 6 | `.class` | `.error-msg` | 提示信息元素 | 低（前端可能改 class） |

推荐先运行 `python scripts/scan_selectors.py http://<device_ip> --auth admin:password` 自动扫描页面元素并生成 Profile 草稿，再人工确认。

如果前端团队愿意配合，最优方案是在关键元素上添加 `data-testid` 属性（Playwright 官方推荐实践），Profile 中使用 `[data-testid='xxx']` 定位。

## 嵌入式家庭网关设备专项测试规则

以下场景为家庭网关设备 Web 管理界面的业界主流检查项，生成用例时按产品阶段覆盖：

### 1. 重启 / 恢复出厂 / 升级一致性（状态持久化）

| 场景 | 规则 | 优先级 |
|---|---|---|
| 重启一致性 | 修改配置 → 重启 → 回读配置应保持不变 | P0 |
| 恢复出厂一致性 | 修改配置 → 恢复出厂 → 所有配置回到出厂默认值 | P0 |
| 升级一致性 | 升级镜像 → 配置按产品策略保持或重置 → 断言与策略一致 | P0 |
| 认证残留 | 恢复出厂/重启/升级后需重新登录，认证状态不应残留 | P1 |

### 2. 业务参数关联逻辑

- 字段联动：A 字段取值变化引起 B 字段显隐/必填变化时（如 WAN 连接类型切换 PPPoE/DHCP 联动账号密码输入框），按判定表覆盖每个分支。
- 跨页联动：一处修改影响另一处显示时，两处都要断言。

### 3. 状态迁移测试（登录/锁定状态机）

认证相关功能按状态机设计用例，覆盖每条迁移边：

```text
[正常] --连续失败 N 次--> [锁定]（N=产品策略，如 10）
[锁定] --输入正确密码--> 仍拒绝（验证锁定生效）
[锁定] --等待锁定时长--> [正常]（验证解锁）
[锁定] --管理手段解锁--> [正常]
```

### 4. 并发会话

| 策略 | 验证规则 |
|---|---|
| 后踢前（业界默认） | 会话 A 登录 → 会话 B 登录 → A 刷新应被踢回登录页 |
| 允许多会话 | 两个会话同时操作同一配置，验证后写覆盖与提示 |
| 拒绝新会话 | 已登录时新会话登录应被拒绝并提示 |

具体策略以产品规格为准，禁止假设。

### 5. 容量与性能（P2）

- 大数据量：列表类页面（连接设备列表、DHCP 客户端、日志）在满载时页面可正常渲染、操作不超时。
- 性能预算：弱 CPU 设备首屏加载时间断言（如状态页 < 3s），超出阈值为性能缺陷。

### 6. 升级异常场景

- 坏镜像：上传校验和不符/非镜像文件应拒绝，设备不应变砖。
- 升级中断：升级中断电后设备应能回退或重试，不应变砖。

### 7. Web 安全基线（对标 OWASP WSTG 精简集）

| 检查项 | 规则 |
|---|---|
| 认证 | 错误凭证拒绝、空凭证拒绝、暴力破解锁定（失败 N 次锁定，验证锁定与解锁） |
| 会话 | 退出登录后访问受保护页面应跳转登录页；会话超时后应重新认证 |
| 越权 | 未登录直接访问受保护 URL 应跳转登录页 |
| 输入注入 | 表单字段提交 XSS payload 应被转义/拒绝，不应执行 |
| 传输 | 生产设备应校验 HTTPS 可用、HTTP 是否按策略跳转 |

### 8. 浏览器兼容性（分级）

| 级别 | 范围 | 时机 |
|---|---|---|
| L1 | Chrome（当前唯一支持） | 每次回归 |
| L2 | Edge、Firefox | 版本发布前 |
| L3 | Safari、移动端浏览器 | 按产品要求 |

兼容性用例复用冒烟子集，通过 profile `browser.type` 切换，不在 MVP 范围内强制。
